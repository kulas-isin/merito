# 用 AI 把對話紀錄轉成 Merito 資料

把 LINE／Slack／Email 的對話紀錄丟給 AI，請它輸出 Merito 格式的 JSON，
再從「設定 → 備份與轉移 → 匯入（合併）」載入。整份流程不需要寫程式。

**適合用來做的事**

- 一次把過去半年的客戶對話整理成客戶檔案與聯絡人
- 從對話裡抓出「講好的金額、答應的交期、追加的需求」變成專案與收款里程碑
- 把吵過的架、踩過的雷整理成經驗記錄
- 依對話裡的態度給出接案評估的初步分數（**只能當草稿，最後要人工確認**）

**先想一下再貼**

對話紀錄裡有客戶的姓名、電話、報價、內部評語。貼進哪個 AI、那家會不會拿去訓練，
自己先確認。敏感的案子建議先把人名與金額代換掉，匯入後再手動改回來。

---

## 流程

1. 匯出對話紀錄（純文字即可）
2. 把下面的〈提示詞範本〉連同對話一起貼給 AI
3. AI 回一段 JSON，存成 `import.json`
4. Merito → 設定 → 備份與轉移 → **匯入（合併）** → 選檔案
5. **人工複查**：AI 會猜錯金額與日期，尤其是「大概三十萬左右」這種模糊講法

> 用「合併」不要用「覆蓋」。合併只會補上新的、更新較新的；覆蓋會把整份資料換掉。

---

## 提示詞範本

複製以下整段，把對話紀錄接在最後面。

````
你是一個資料整理助理。我會給你一段與客戶的對話紀錄，
請你轉成下面這個 JSON 結構，只輸出 JSON，不要有任何解釋文字。

規則：
1. 只寫對話裡真的有講到的資訊。沒講到的欄位就留空字串或省略，不要猜、不要編。
2. 金額只填明確數字。「大概三十萬」寫 300000 並在 note 註明「口頭約略」；
   「再看看」「之後報」則留空。
3. 日期一律 YYYY-MM-DD。相對日期（「下週三」）換算成絕對日期，
   換算基準日是 __今天的日期__，換算不出來就留空。
4. id 自己編，格式用 "ai-" 開頭加流水號，例如 "ai-c1"、"ai-p1"。
   同一個客戶在不同區塊要用同一個 id 串起來（projects.clientId 要對得上 clients.id）。
5. 每一筆記錄都要有 updatedAt，值用當下時間的 ISO 8601（例如 "2026-08-01T10:00:00Z"）。
   沒有這個欄位，匯入時會被既有資料蓋掉。
6. updatedBy 一律填 "AI 匯入"。
````

## 讓 AI 也給評估分數（選用）

要 AI 直接產出接案評估，把下面這段接在上面的提示詞後面，
並把 `assessments` 從空陣列改成實際輸出。

````
另外請依對話內容做一次接案評估，放進 assessments。
七題各給 1–5 分（1 = 差／高風險，5 = 好），依序是：

1. 預算 vs 工作量是否成比例
2. 需求清晰度
3. 是否為第一次外包（沒換過團隊）
4. 決策鏈是否穩定
5. 新需求的付費意願
6. 溝通態度是否互惠
7. 合作安全度（客戶自行接手的風險，5 = 單純委託，1 = 客戶有工程能力可能自己做）

對話裡沒有足夠資訊判斷的題目一律給 3（中性），不要用猜的給極端分數。
total 是七題總和。verdict 依 total 決定：>=27 填 "go"，>=18 填 "caution"，其餘 "avoid"。
flags 放所有給 1 或 2 分的題目對應文字，用下列固定字串：

1 → "預算與工作量不成比例"
2 → "需求模糊，易膨脹"
3 → "曾換過團隊，高風險"
4 → "決策鏈不穩，需求會反覆"
5 → "付費意願低，易凹免費"
6 → "伸手牌傾向：只索取不給予"
7 → "客戶有工程能力，留意被取代"

格式：
{
  "id": "ai-a1",
  "clientId": "ai-c1",
  "date": "YYYY-MM-DD",
  "scores": [3,2,3,1,2,2,4],
  "total": 17,
  "verdict": "avoid",
  "flags": ["需求模糊，易膨脹", "決策鏈不穩，需求會反覆", "付費意願低，易凹免費", "伸手牌傾向：只索取不給予"],
  "note": "判斷依據，寫清楚是對話裡哪句話讓你這樣打分",
  "by": "AI 匯入",
  "updatedAt": "ISO 時間", "updatedBy": "AI 匯入"
}
````

AI 給的分數當草稿看就好。它讀不出語氣、也不知道你跟對方的歷史，
`note` 欄要求它寫判斷依據，就是方便你回頭一句一句核對。

## 常見狀況

**匯入後資料沒出現**
多半是缺 `id`，或 `updatedAt` 沒填。沒有 `id` 的記錄會被直接濾掉；
`updatedAt` 空的話，遇到同 id 的既有資料會輸給對方。

**客戶重複了一份**
AI 編的 `id` 跟系統既有的對不上，所以被當成新客戶。
兩個做法：匯入前先把 JSON 裡的 `id` 改成系統裡的既有 id（在客戶檔案頁的網址列看得到），
或匯入後手動把重複的那筆刪掉、資料併過去。

**只想更新既有客戶的某些欄位**
JSON 只放要改的那幾筆，`id` 用既有的，選「匯入（合併）」。
合併是逐筆比對，不會動到 JSON 裡沒提到的記錄。

**先試小的**
第一次別一口氣丟三年份。先拿一個客戶的對話跑一遍，
確認 AI 的格式跟你的判斷都對得上，再放大。
匯入前記得先「匯出 JSON 備份」，出事可以還原。
